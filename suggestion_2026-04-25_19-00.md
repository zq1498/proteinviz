# DEPLOYMENT SUGGESTION
## What
`render_report()` in `tools/report.py` is fully stubbed — the pipeline produces metrics and plots but no human-readable artifact that ties them together.

## Why Now
Phase 1's stated milestone is "wire a minimal end-to-end report." Every other layer (extraction, plotting, analysis) is in place; the report is the only thing preventing a full pipeline run from producing a shareable output.

## Suggested Addition
A Markdown renderer that combines metrics, sequence flags, and plot references into a single file. Markdown requires no new dependencies, renders in browsers/notebooks, and is trivially diff-able in git.

```python
from datetime import datetime
from pathlib import Path
from tools.extract import ExtractedMetrics, composite_score

def render_report(
    job_id: str,
    metrics: list[ExtractedMetrics],
    seq_flags: list[str],          # flat strings from analyze_sequence()
    plot_dir: Path,
    out_path: Path,
    weights: dict | None = None,   # pass-through to composite_score
) -> None:
    kw = dict(weights=weights) if weights else {}
    ranked = sorted(metrics, key=lambda m: composite_score(m, **kw), reverse=True)
    best = ranked[0]
    score = composite_score(best, **kw)

    interp = (
        "strong candidate (score > 0.70)"   if score > 0.70 else
        "moderate (score 0.50–0.70)"         if score > 0.50 else
        "weak / likely non-binder (< 0.50)"
    )

    lines = [
        f"# Prediction Report: {job_id}",
        f"_Generated {datetime.now().strftime('%Y-%m-%d %H:%M')} · backend: {best.backend}_\n",
        "## Executive Summary",
        f"Best model: **{best.model_id}** — composite score **{score:.3f}** ({interp})",
        f"Mean pLDDT: {best.mean_plddt:.1f} | pTM: {best.ptm:.3f}"
        + (f" | ipTM: {best.iptm:.3f}" if best.iptm is not None else ""),
        "",
        "## Model Rankings\n",
        "| # | Model | Composite | Mean pLDDT | pTM | ipTM |",
        "|---|-------|-----------|------------|-----|------|",
    ]
    for i, m in enumerate(ranked, 1):
        cs = composite_score(m, **kw)
        iptm = f"{m.iptm:.3f}" if m.iptm is not None else "—"
        lines.append(f"| {i} | {m.model_id} | {cs:.3f} | {m.mean_plddt:.1f} | {m.ptm:.3f} | {iptm} |")

    if seq_flags:
        lines += ["", "## Sequence Flags\n"]
        lines += [f"- {f}" for f in seq_flags]

    plots = sorted(plot_dir.glob("*.png"))
    if plots:
        lines += ["", "## Plots\n"]
        lines += [f"- [{p.name}]({p.resolve()})" for p in plots]

    out_path.write_text("\n".join(lines) + "\n")
```

# NOVEL SUGGESTION
## What
Pre-compute the target's MSA once and reuse it across an entire peptide panel, eliminating N−1 redundant MSA jobs for the primary VEGF165 × 20-peptide use case.

## Why It's Worth Considering
ColabFold accepts a pre-built `.a3m` file directly via `--a3m` — this is the intended path for paired-chain complexes with a known target. For a 20-peptide panel, the current flow recomputes VEGF165's MSA 20 times; with 7h MSA waits observed in `smoke_test`, that's the difference between ~140h and ~14h of total wall time (one target MSA + 20 short peptide single-sequence lookups). The tradeoff is a two-step CLI workflow instead of one.

## Sketch

```python
# tools/predict.py — add to write_fasta() or a new helper

def build_paired_a3m(
    peptide_seq: str,
    peptide_id: str,
    target_a3m: Path,
    out_dir: Path,
) -> Path:
    """
    Produce a ColabFold-compatible paired A3M:
      chain A = peptide (single sequence, no MSA)
      chain B = target (pre-computed A3M)
    The '*' line is the ColabFold chain-break separator.
    """
    out = out_dir / f"{peptide_id}_paired.a3m"
    with out.open("w") as f:
        f.write(f">{peptide_id}\n{peptide_seq}\n*\n")
        f.write(target_a3m.read_text())
    return out
```

CLI addition to `predict()`:

```
--target-a3m PATH   Pre-computed target MSA (.a3m). When supplied, the peptide
                    chain uses single-sequence mode and no MSA lookup is run.
                    Produces a paired A3M passed to colabfold_batch via --a3m.
```

Workflow for the full panel:

```bash
# Step 1 — once per target
python -m tools.predict --sequence VEGF165_SEQ --msa-only --out jobs/vegf165_msa/

# Step 2 — once per peptide (no MSA wait)
for pep in peptides/*.fasta; do
  python -m tools.predict --fasta $pep --target-a3m jobs/vegf165_msa/vegf165.a3m \
    --out jobs/$(basename $pep .fasta)/
done
```

The `--msa-only` flag (also new, but trivial to add) runs ColabFold just long enough to produce the `.a3m` then exits before structure prediction.

## Where It Fits
Primarily `tools/predict.py` (`predict()` dispatcher + argument parser). The `build_paired_a3m()` helper could live in `tools/msa.py` since MSA handling is already there.

# REFACTOR AND REFINE SUGGESTION
## What
`composite_score()` embeds its three weights as bare float literals — when calibration time comes, a code edit is required and the weights used for any given run are invisible in the output.

## Why It's Worth Doing
The project explicitly flags these weights as uncalibrated placeholders. Externalizing them to a named dict costs two lines and makes experiments reproducible: different weight trials become different dict arguments, and the weights can be echoed into the report artifact without any additional work.

## Concrete Change

```python
# Before (tools/extract.py)
def composite_score(m: ExtractedMetrics) -> float:
    return (
        0.5 * m.ranking_score
        + 0.3 * (m.mean_plddt / 100)
        + 0.2 * (m.interface_plddt / 100)
    )
```

```python
# After
DEFAULT_SCORE_WEIGHTS: dict[str, float] = {
    "ranking": 0.5,
    "mean_plddt": 0.3,
    "interface_plddt": 0.2,
}

def composite_score(
    m: ExtractedMetrics,
    weights: dict[str, float] = DEFAULT_SCORE_WEIGHTS,
) -> float:
    w = weights
    return (
        w["ranking"] * m.ranking_score
        + w["mean_plddt"] * (m.mean_plddt / 100)
        + w["interface_plddt"] * (m.interface_plddt / 100)
    )
```

All existing call sites pass no `weights` argument and remain unchanged. When the report renders, append the weights used:

```python
# In render_report(), after the executive summary line:
lines.append(f"_Score weights: {weights or DEFAULT_SCORE_WEIGHTS}_")
```

## Where It Lives
`tools/extract.py` — `composite_score()` function and its call sites. `DEFAULT_SCORE_WEIGHTS` should also be re-exported or imported by `tools/report.py`.
